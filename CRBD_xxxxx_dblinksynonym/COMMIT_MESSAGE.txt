Fix DBLINK synonym to preserve schema when explicitly specified

When using DBLINK with synonym, remote SQL was incorrectly including
schema prefix (e.g., "public.emp") even when user didn't specify it,
causing "Unknown class public.emp" errors on remote server.

Changes:
- Preserve schema in remote SQL if user explicitly specified it
  (e.g., "public.emp@cubrid_conn" -> "public.emp")
- Strip schema only when not specified (e.g., "emp@cubrid_conn" -> "emp")
- Updated pt_convert_dblink_synonym, pt_mk_spec_derived_dblink_table,
  and pt_remake_dblink_select_list to check for schema presence

Files modified:
- src/parser/parser_support.c (pt_convert_dblink_synonym,
                                pt_mk_spec_derived_dblink_table)
- src/parser/name_resolution.c (pt_remake_dblink_select_list)
